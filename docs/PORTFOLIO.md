# Портфолио: CRM игрового клуба + ИИ-ассистент

## Что это
CRM PlayStation/компьютерного клуба: Django REST API, веб-дашборд для персонала,
Telegram-бот для гостей (регистрация, брони, QR, рефералки, бонусы).

## Моя роль (AI-assisted development)
Я работал как оператор: ставил задачи, принимал решения по скоупу,
читал каждый diff и проверял запуском. ИИ ускорял рутину — архитектуру,
ревью и тесты держал я.

## Что сделано с помощью ИИ
1. **Аудит** — разбор 4 компонентов, поиск секретов в коде (токен в
   `settings.py`/`docker-compose`), багов (рефералка слала неверное поле,
   брони не видели активные сессии) и N+1 в сериализаторах.
2. **Безопасность** — env-конфиг, `IsManagerOrService`/`IsAdminOrService`,
   `login_required` на дашборды, троттлинг DRF, `.gitignore`, `.env.example`.
3. **Логика** — aware-даты броней, автозакрытие сессий и броней (no-show),
   реферальные бонусы через `F()` + транзакции, ручная корректировка бонусов,
   напоминание за 10 минут до конца сессии.
4. **Скорость** — `PlaceSerializer` без N+1, аналитика выручки одним запросом
   (`TruncDate`) вместо 30, occupancy одним запросом вместо 24×7.
5. **Качество** — 8 автотестов (`crm_core`, `loyalty`), пагинация клиентов,
   CSV-экспорт, редизайн (aurora-фон, анимации, live-статус на лендинге).

## Как проверить (демо 5 минут)
```bash
pip install -r requirements.txt
python manage.py migrate
python manage.py test crm_core loyalty   # 8 тестов, ~0.05с
python manage.py runserver               # http://127.0.0.1:8000/
# / — лендинг с live-статусом, /dashboard/ — операции, /super/ — аналитика
cd tg_bot && npm install && node index.js  # /start в Telegram
```

## Границы инструмента
ИИ дважды ошибался: оставлял мусорный код в аналитике и затирал строку
функции при правке — я ловил это чтением diff и `manage.py check`.
Финальные решения (удалить мини-апп, разделить роли staff/superuser)
принимал я, исходя из скоупа.
